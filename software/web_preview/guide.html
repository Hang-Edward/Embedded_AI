如何开发一个类似 AI 智能眼镜能力的桌面原型

目标不是第一步就做成眼镜外壳，而是先实现智能眼镜最核心的能力： 摄像头实时读取画面，麦克风接收语音问题，千问视觉/Omni API 理解图像和语音， 第一阶段先由 Windows 电脑端 C++负责桥接、联网与安全校验，NUCLEO负责按键、LED、蜂鸣器、震动和显示/投影反馈。 Raspberry Pi 作为第二阶段升级路线，用于脱离电脑运行。

建议下单组合

稳妥优先，不追极限省钱
  • 第一阶段必须买：NUCLEO-F446RE、Gravity 或 Grove 扩展板、USB-A 转 Mini-B 数据线。
  • 先不买：OLED、按键、LED、蜂鸣器、面包板/杜邦线。图片里的套件已经包含这些，先用已有模块验证。
  • 建议买：震动马达模块、支架、透明亚克力立牌。套件里有 130 直流电机和电机驱动，但不等于安全好用的震动反馈模块。
  • 第二阶段后买：Raspberry Pi、Pi 电源、microSD、Pi 散热外壳、投影仪、独立 USB 麦克风、DRV2605L 触觉驱动。
  • 不用买：ST-Link 下载器。NUCLEO 板载 ST-LINK，正常不需要额外购买。

为什么加 Raspberry Pi

NUCLEO 不是联网主脑
  • NUCLEO 适合控制 GPIO、OLED、LED、蜂鸣器、按键和震动，实时稳定。
  • Raspberry Pi 适合接 USB 摄像头、USB 麦克风、Wi-Fi、文件系统、OpenCV、HTTPS 和千问 API。
  • 如果给 NUCLEO 加 Wi-Fi 模块，它仍然很难处理 C270 摄像头、图片上传、TLS 证书、复杂 JSON 和 UI。
  • 第一阶段不急着买 Raspberry Pi；等 Windows 原型稳定后，再把 C++主程序迁移过去。
  • 最终上台时，Raspberry Pi 和 NUCLEO 都藏在原型底座里，外面看起来就是一个独立设备，不需要笔记本。

显示方案怎么选

我的建议：先投影，后眼镜
  • 0.96寸 OLED：最便宜、最好接线，但只能显示短句，视觉冲击力弱。
  • 小型投影 + 亚克力板：答辩效果最好，能展示对话、解题步骤和画面描述，是当前最推荐路线。
  • HDMI 小屏：比 OLED 清楚，适合放在桌面原型上，但没有投影的“未来感”。
  • micro-OLED/近眼光学模组：最像智能眼镜，但成本、采购、供电、光路和佩戴结构都更难，建议作为第二阶段。

软件开发步骤

C++主体清晰
  1. 先写 STM32 固件：按键、LED、蜂鸣器、OLED、震动马达能独立工作。
  2. 定义串口协议：例如 CAPTURE、PROJECTOR:TEXT、LED:RED。
  3. 写 PC端 C++串口程序，能收到 STM32 按键事件。
  4. 接入 OpenCV，用 C++从摄像头保存 scene.jpg。
  5. 接入麦克风输入，可先用语音转文字，再发送给模型。
  6. 调用千问视觉/Omni API，要求返回结构化 JSON。
  7. C++校验 AI 返回内容，只允许白名单动作。
  8. 把解题步骤、画面描述、风险等级发送到投影/屏幕和 STM32。
  9. 生成运行日志和答辩用 HTML 报告。

C++大作业要求适配

STM32 是硬件子系统，PC端 C++ 是评分主体

根据课程 PDF，项目需要体现面向对象、UI、随机文件读写更新、至少 5 个类、继承层级不少于 2、源码不少于 2000 行。 因此不要只提交 STM32 固件。更稳妥的做法是：提交一个 PC端 C++ 桥接程序作为主项目， STM32 固件作为硬件反馈模块，网页作为展示层。

课程要求 本项目对应实现
Class / Object / Encapsulation CameraService、SpeechService、QwenVisionClient、SerialDevice、AuditLogStore 等类封装各模块。
Inheritance / Polymorphism Device -> InputDevice -> CameraInput，以及 OutputDevice -> ProjectorOutput/NucleoFeedback。
不少于 5 个类 计划设计 12 个以上 C++类，覆盖设备、AI 客户端、任务、日志、UI、配置、测试等。
继承层级不少于 2 设备抽象层至少三层：Device、InputDevice/OutputDevice、具体设备类。
UI needed PC端 C++可做控制台菜单或 Qt/网页本地 UI；当前 HTML 页面可作为展示 UI。
Random file processing 用二进制或 JSON 审计日志文件支持写入、读取、按记录 ID 更新，例如修改风险确认状态。
源码不少于 2000 行 PC端 C++主程序 + STM32固件 + 测试/示例数据，足够达到行数要求，但应避免无意义灌水。

组装接线建议

NUCLEO 采购后按实物重画接线

这张图是早期 Blue Pill 版的接线参考，用来解释面包板、电源轨和模块接线关系。 你已经决定使用 NUCLEO 后，最终接线应按 NUCLEO-F446RE 的 Arduino R3 / ST Morpho 引脚重新画。 采购到手后，把开发板和扩展板照片发给我，我会给你重画“每根线插哪里”的 NUCLEO 专用图。

旧 Blue Pill 引脚 接到哪里 NUCLEO 中的对应思路
3.3V 面包板红色电源轨、OLED VCC、按键模块 VCC 给 3.3V 模块供电
GND 面包板蓝色地线轨、所有模块 GND 共地，所有模块必须连在一起
PB6 OLED SCL I2C 时钟线
PB7 OLED SDA I2C 数据线
PA0 按键模块 OUT 触发拍照、提问或确认
PA1 220Ω 电阻 -> LED 长脚；LED 短脚 -> GND 状态灯
PA2 有源蜂鸣器模块 IN 风险提示音
PA3 震动马达驱动模块 IN 震动提醒
PA9 USB-TTL 模块 RX STM32 发消息给电脑
PA10 USB-TTL 模块 TX 电脑发命令给 STM32
  • NUCLEO-F446RE 自带 ST-LINK，正常不需要再买 ST-Link 下载器。
  • NUCLEO 推荐搭配 Gravity 或 Grove 扩展板，用模块线连接，少用散乱杜邦线。
  • OLED：接 STM32 的 I2C 引脚，通常是 SCL、SDA、3.3V、GND。
  • 按键：一端接 GPIO，一端接 GND，代码中开启上拉输入。
  • LED：GPIO 串联电阻后接 LED，再接 GND。
  • 有源蜂鸣器：GPIO 控制，注意电流不够时用三极管或模块。
  • 震动马达：建议用驱动模块或三极管，不要直接让 GPIO 带电机。

千问 API 接入建议

真实 + 离线双模式

如果要做出“智能眼镜”的感觉，建议调用有视觉能力的千问模型处理图片， 或使用支持音频/图像输入的多模态实时接口做语音问答。STM32 不跑大模型， PC端 C++负责把图片和语音问题发给 API，再解析返回结果。

同时保留离线演示模式：提前准备几张图片和模拟 JSON，防止答辩现场网络或 API 出问题。
